# WhiteListSync 内网插件

该插件适用于 Paper/Leaves 1.21、Java 17。它在 `AsyncPlayerPreLoginEvent` 中异步调用 Go 白名单端点；只有收到 HTTP 200、JSON 明确包含 `allowed: true` 和有效尝试 ID 才允许预登录。PlayerJoin 后异步确认该 ID；确认失败会踢出玩家。玩家退出通过 `/logout/{name}` 上报，插件每 30 秒上报在线名册以续租 90 秒在线计时租约。

## 配置

将 `目标文件/plugins/whitelist/WhiteListSync-2.0.1.jar` 放入服务器 `plugins` 目录后启动一次，再编辑 `plugins/WhiteListSync/config.yml`：

```yaml
api-url: "http://10.20.0.5:18094"
whitelist-token: "<本游戏服的 whitelist scope token>"
request-timeout-seconds: 3
```

`api-url` 必须使用 loopback、RFC1918、IPv6 ULA 或 link-local 的 IP 字面地址；域名会被拒绝，避免每次 HTTP 请求重新解析时因 DNS 变化把白名单 token 发往公网。运行 `gbcserver plugin-token` 交互选择白名单并填写游戏服可访问的服务端私网 IP，也可在管理员网页“插件接入”页签发令牌。自动化部署可用 `gbcserver plugin-token issue --db <db> --server-id <id> --scope whitelist`。`<id>` 必须与数据库 `serverID` 配置一致，也要用于同一游戏服的兑换 token；两种 token 的 scope、`token_id` 和 secret 各自独立，不能复用。启动后不要把 token 放入公开日志、命令行示例或版本控制。

## 当前限制

Go 和插件源码现已实现 `/check`、`/join`、`/heartbeat` 与租约回收，Go 测试、插件离线打包已通过；Paper/Leaves 集成仍未完成。租约到期会停止计时，心跳恢复时重新开段；断网时最多多计 90 秒，恢复间隔按保守策略不计入。上线前必须用目标服务端验证事件顺序、与其他插件交互和断网恢复行为。

## 网络要求

- WhiteListSync 直接通过内网访问 Go 白名单 listener，不经过公网反向代理。Go listener 仅监听 loopback、私有或 link-local IP，HTTP 对端也必须来自这类内网地址；程序忽略 `X-Forwarded-For`。
- 配置文件只需填写 `plugin.whitelistListen` 监听地址，不需要配置来源 CIDR。游戏服与 Go 服务同机时使用默认 `127.0.0.1:18094`；跨机器时填写 Go 服务端的私网 IP，并在主机防火墙中只允许游戏服访问。
- 白名单 listener 使用内网 HTTP，令牌仍应只存放在游戏服受限配置中。兑换插件使用独立的 `couponListen` 和 `coupon.redeem` token，不与白名单接口或令牌复用。
## 构建

在有 JDK 17 和 Maven 的环境执行：

```powershell
mvn -o -f .\plugins\whitelist\pom.xml clean package
```

打包结果为 `目标文件/plugins/whitelist/WhiteListSync-2.0.1.jar`。部署前还需在实际 Paper/Leaves 版本上验证异步预登录事件顺序以及与其他登录插件的交互。
