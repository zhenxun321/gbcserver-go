# CouponPlugin 使用说明

## 适用环境

- 目标服务端: Leaves 1.21.8+ / Paper 1.21 API
- Java: 17+
- 构建产物: `目标文件/plugins/coupon/CouponPlugin-1.3.1.jar`

## 功能

玩家输入兑换码后，插件会请求配置中的兑换码 API，并把返回的物品奖励发放到玩家背包。背包满时，多余物品会掉落在玩家脚下。

## 命令与权限

| 命令 | 使用对象 | 权限节点 | 默认权限 |
| --- | --- | --- | --- |
| `/coupon <code>` | 玩家 | `coupon.use` | 全员 |

## 配置

配置文件: `plugins/CouponPlugin/config.yml`

```yaml
api-url: "http://127.0.0.1:18095/api"
coupon-token: "CHANGE_ME"
max-item-amount: 2304
```

- `api-url`: Go 兑换 listener 的内网地址，必须使用 loopback、RFC1918、IPv6 ULA 或 link-local IP 字面地址并以 `/api` 结尾。默认 `http://127.0.0.1:18095/api` 适用于游戏服与 Go 服务同机；跨机器时填写 Go 服务端私网 IP，例如 `http://10.20.0.5:18095/api`。
- `coupon-token`: 只授予 `coupon.redeem` 权限的每服 Bearer token，必须改成新 Go 服务签发的真实值，否则兑换会被拒绝。旧版 `server-token` 配置不会自动读取；迁移时必须签发并配置新的兑换 scope token。
- `max-item-amount`: 单个奖励物品最大数量，默认 2304。

使用 `gbcserver plugin-token` 交互选择兑换插件并填写游戏服可访问的服务端私网 IP，也可在管理员网页“插件接入”页签发令牌。自动化部署可使用显式 `plugin-token issue` 参数。命令或网页生成的配置会自动使用当前兑换 listener 端口和 `/api` 路径。

## 使用方法

1. 将 `目标文件/plugins/coupon/CouponPlugin-1.3.1.jar` 放入服务端 `plugins` 目录，并移除旧版本 JAR。
2. 启动一次服务端生成配置文件。
3. 修改 `coupon-token` 为本游戏服独立签发、只拥有 `coupon.redeem` scope 的 Bearer token。不要把该值与内网白名单 token 复用。
4. 重载或重启服务端。
5. 玩家执行 `/coupon <code>` 兑换奖励。

## 构建

在仓库根目录执行：

```powershell
mvn -f .\plugins\coupon\pom.xml clean package
```

JAR 输出到 `目标文件/plugins/coupon/CouponPlugin-1.3.1.jar`。

## 注意事项

- 该命令默认全员可用；如需限制，可在权限插件中撤销 `coupon.use`。
- 同一玩家同时只能有一个兑换请求在处理中，避免并行提交。
- 插件通过 JSON POST 请求兑换接口，在 `Authorization: Bearer <token>` 中发送 `coupon.redeem` token，并在请求体及 `X-Request-ID` header 中携带持久化的随机 `requestId`。遇到网络故障、HTTP 408/425/429 或 5xx 时自动进行三次有限重试，每次复用相同 ID；其他非成功 HTTP 状态不会当作可重试故障。重试耗尽后保留 ID，玩家再次输入相同兑换码即可恢复同一服务端结果。
- Go 服务必须在同一 SQLite 事务中消费兑换码并保存该 request ID 对应的响应快照。插件会先把奖励快照原子保存到本地账本，再写入玩家背包并要求 Bukkit 保存玩家数据；随后先原子清除该兑换的 request ID，再原子清除待发账本，任一步本地写入失败都会保留恢复记录。游戏服重启后玩家下次加入时自动重试待发奖励。若在物品已进入背包、账本清理前崩溃，会重复发奖；当前按已确认的策略接受这种小概率重复，以降低奖励丢失风险。插件数据目录必须限制为 Minecraft 服务账号和管理员可读。
- 待发账本保存在 `plugins/CouponPlugin/pending-deliveries.yml`，不保存兑换码明文；同一游戏服不要让多个进程共享该账本。
- 游戏服直接通过内网 HTTP 连接 Go 程序的 `couponListen`（默认 `127.0.0.1:18095`），不经过公网反向代理。跨机器部署时让 Go 监听服务端私网 IP，并用主机防火墙限制游戏服来源；不要把插件 listener 暴露到公网。
