# GBC Server 部署说明

发布 ZIP 包含服务端程序和 gbcserver-go 发布说明，不含插件 JAR 或运行数据。网页和通用资源已嵌入程序；SQLite、头像和商品图片保存在独立数据目录中。

## 目录与配置

程序首次运行只会在部署根目录创建 `gbcserver/`。Linux 默认部署根目录是当前用户的 `$HOME`，Windows 默认是程序所在目录；程序放在 Windows 的 `bin/` 时，根目录是 `bin/` 的上级目录。运行配置全部保存在 `gbcserver/gbcserver.db` 的 `app_config` 表中，不再生成或读取 JSON 配置文件。使用 `--data-dir` 时，参数值就是自定义运行数据文件夹本身。

运行对应平台的 Go 程序，首次启动会自动创建数据库和运行目录。已有数据迁移到其他位置后，用 `--data-dir <gbcserver目录>` 指定该目录。

`gbcserver/` 中的内容如下：

| 路径 | 用途 |
| --- | --- |
| `gbcserver.db` | Web、插件和运行配置共用的 SQLite 数据库 |
| `web/` | 用户上传的商品图片和静态文件 |
| `web/items/` | 迁移或上传后的商品图片 |
| `avatars/` | 用户头像 |
| `server.pem` | 可选 TLS 证书链 |
| `server.key` | 可选 TLS 私钥 |
| `gbcserver.log` | Linux 后台启动日志 |
| `gbcserver.pid` | Linux 后台进程 PID |
| `.gbcserver-control.json`、`.gbcserver-control.sock` | 本机 `reload`/`stop` 管理通道状态，服务退出时删除 |

不要手动编辑 SQLite。设置命令和管理员网页会校验值并永久写入数据库；修改端口、管理员入口或 listener 后，可在网页点“重新加载服务”，也可运行 `reload --data-dir <data目录>`。

SQLite 可能包含玩家账户、密码哈希、签到记录、商品、兑换码和端口映射，属于敏感数据。Linux 部署后限制目录权限：`chmod 700 gbcserver && chmod 600 gbcserver/gbcserver.db`；Windows 使用仅服务账户和管理员可读的 ACL。不要把管理员口令、TOTP、插件 token、TLS 私钥或 SMTP 凭据放入发布包。

新数据库会在首次启动时创建。旧 Node JSON 配置不会自动迁移；首次启动后完成管理员初始化，再按需配置 SMTP、HTTPS 证书和业务参数。管理员初始化时双重验证可以留空，登录后可在管理页面生成二维码并验证启用。数据库和运行数据不进入发布 ZIP。

English: The database is created on first start. Old Node.js JSON settings are not migrated automatically. Complete administrator setup, then configure SMTP, HTTPS certificates, and service settings as needed. Two-factor authentication is optional during setup and can be enabled later from the administration page with a locally generated QR code and a verification code. The release ZIP does not include databases or runtime data.

## 启动命令

```text
gbcserver start [--data-dir <data目录>] [--background|--tray] [--autostart|--no-autostart]
gbcserver httpport <端口> [--data-dir <data目录>]
gbcserver httpsport <端口> [--data-dir <data目录>]
gbcserver admin-path <入口> [--data-dir <data目录>]
gbcserver admin-username <账户> [--data-dir <data目录>]
gbcserver admin-password <密码> [--data-dir <data目录>]
gbcserver reload [--data-dir <data目录>]
gbcserver stop [--data-dir <data目录>]
gbcserver help [命令]
```

端口和三个 admin 设置是顶层命令，不是 `start` 参数。运行配置页也能完成这些设置，保存后可直接在页面重新加载服务。命令完成后会输出已写入数据库；`admin-password` 只保存 bcrypt 哈希，不保存明文。密码长度为 8 至 72 字节。管理员入口会自动规范为 `/入口`，不能使用根路径 `/`，也不能包含空格、`?` 或 `#`。

示例：

```powershell
./gbcserver-windows-amd64.exe httpport 8080 --data-dir 'D:/gbc/gbcserver'
./gbcserver-windows-amd64.exe httpsport 8443 --data-dir 'D:/gbc/gbcserver'
./gbcserver-windows-amd64.exe admin-path console --data-dir 'D:/gbc/gbcserver'
./gbcserver-windows-amd64.exe admin-username admin --data-dir 'D:/gbc/gbcserver'
./gbcserver-windows-amd64.exe admin-password 'change-this-password' --data-dir 'D:/gbc/gbcserver'
./gbcserver-windows-amd64.exe start --data-dir 'D:/gbc/gbcserver'
./gbcserver-windows-amd64.exe reload --data-dir 'D:/gbc/gbcserver'
./gbcserver-windows-amd64.exe stop --data-dir 'D:/gbc/gbcserver'
```

Linux：

```sh
chmod +x ./gbcserver-linux-amd64
./gbcserver-linux-amd64 httpport 8080
./gbcserver-linux-amd64 admin-path admin
./gbcserver-linux-amd64 start --background
./gbcserver-linux-amd64 reload
./gbcserver-linux-amd64 stop
```

Linux 无参数运行等价于 `start --background`；Windows 双击等价于 `start --tray`。同一台机器只允许一个服务实例；再次执行 `start` 会提示已有实例并退出。`help`、端口设置、admin 设置、自启管理和令牌管理命令仍可执行。`reload` 和 `stop` 不会启动第二个服务进程。

## Web 与 TLS

HTTP 默认监听 `0.0.0.0:80`，HTTPS 默认端口为 `443`。程序检测到 `gbcserver/server.pem` 和 `gbcserver/server.key` 都是有效 TLS 文件时，同时启动 HTTP 与 HTTPS；证书缺失或无效时只启动 HTTP。`httpport` 和 `httpsport` 只修改端口，不改变监听地址；Web 始终绑定全部 IPv4 网卡。

绑定 80/443 需要 Linux root 或 `CAP_NET_BIND_SERVICE`；开发环境可设置高位端口。证书放在 `gbcserver/`，不要把私钥放进分发 ZIP 或提交到代码仓库。

## 管理员初始化与管理页

默认管理员入口基路径是 `/admin`，可通过 `admin-path` 修改。访问 `/admin` 会跳转到 `/admin/`，管理员页面的样式和脚本从该安全入口下加载。首次管理员初始化只接受本机回环连接；远程管理时请先用 SSH 端口转发到服务器本机，再打开初始化页面。填写管理员账户和至少 8 位密码；TOTP secret 可以留空。启用或更换双重验证时，页面会本地生成二维码，添加到身份验证器后输入一次新验证码确认；关闭时必须输入管理员密码和当前验证码。

管理员登录使用独立的管理员 session，与玩家 session 完全隔离。管理员 session 通过 `X-Admin-Session` 请求头访问管理 API。管理员页面可以查看和修改数据库中的运行配置；修改端口、入口或 listener 后执行 `reload` 让服务重新绑定。

English: Initial administrator setup accepts only loopback connections. For remote administration, use SSH port forwarding to the server before opening the setup page. Administrator sessions are separate from player sessions. Send the administrator session in the `X-Admin-Session` header when calling management APIs. The administration page can view and update runtime settings in the database. Run `reload` after changing ports, the administrator path, or plugin listeners.

首次初始化只检查 TCP 来源和转发头。反向代理必须保留可信的客户端地址；不要允许外部请求伪造 `X-Forwarded-For`。自定义代理时，请将管理页仅绑定在本机或可信私网。

English: First setup checks the TCP peer and forwarded address. A reverse proxy must preserve the trusted client address; do not allow external requests to spoof `X-Forwarded-For`. Bind the administration page to loopback or a trusted private network when using a custom proxy.

管理页面可编辑系统名称、玩家登录页标题、状态页标题与页脚、HTTP/HTTPS 端口、管理员入口/账户/密码/TOTP、白名单和兑换 listener 地址、静态与头像目录、TLS 文件路径、请求限制、白名单服务标识、Webhook、签到/授权、正版查询、SMTP、状态探测和 Mojang 参数。站点文案保存在 SQLite，保存后重新加载页面即可生效；密码提交后只保存 bcrypt 哈希，TOTP 和 SMTP 密码只显示“已配置”状态。

English: The administration page can edit site names and page copy, HTTP/HTTPS ports, administrator settings, plugin listeners, static and avatar directories, TLS file paths, request limits, whitelist service ID, webhook, check-in and authorization settings, premium account lookup, SMTP, status probes, and Mojang settings. Site copy is stored in SQLite and applies after reloading the page. Administrator passwords are stored only as bcrypt hashes; TOTP secrets and SMTP passwords are shown only as configured or not configured.

### 网页邮件与服务器状态配置

这些值在管理员入口的“运行配置 → 邮件与状态”中填写，保存后永久写入 `gbcserver.db`；端口、状态目标、SMTP 和状态 API 的改动需要执行 `reload` 才会被运行中的服务加载。站点名称和登录/状态页文案在“站点文案”中维护，不需要重载服务。不要把 SMTP 密码写进命令历史或日志。

SMTP 字段含义：

| 字段 | 填写方式 |
| --- | --- |
| `mailHost` | SMTP 主机名或 IP，例如 `smtp.example.com`；留空则不启用注册/找回密码邮件。 |
| `mailPort` | `465` 配合 `mailSecure=true` 使用 SMTPS；`587` 通常配合 `mailSecure=false`，程序会优先协商 STARTTLS。 |
| `mailUsername` | SMTP 登录用户名；无认证服务可留空。 |
| `mailPassword` | SMTP 登录密码；页面只显示“已配置”，留空表示保持原值。 |
| `mailFromName` | 邮件显示名称，可留空。 |
| `mailFromAddress` | 发件地址，必须是 SMTP 服务允许的地址。启用 SMTP 时必填。 |
| `mailSecure` | `true` 为连接即 TLS（适合 465）；`false` 为明文连接并在服务器支持时升级 STARTTLS（适合 587）。 |

邮件配置用于注册验证码和密码找回验证码。保存后用玩家注册或找回密码流程发送一封测试邮件；若没有配置 SMTP，接口会明确返回邮件服务不可用，不会把验证码写入日志。

服务器状态字段含义：

| 字段 | 填写方式 |
| --- | --- |
| `statusServers` | 管理员网页使用 JSON 列表维护，例如 `[{"name":"电信线路","host":"v4.example","port":25565}]`。名称支持中文；启动命令仍兼容 `名称=主机:端口,名称2=主机2:端口` 和旧 Node 的 `defaultPort` 字段。空列表表示不展示状态目标。 |
| `statusAPIs` | 管理员网页使用 JSON 列表维护，例如 `[{"name":"mcsrvstat","url":"https://api.mcsrvstat.us/3/{hostport}"}]`。模板支持 `{host}`、`{port}`、`{hostport}`；启动命令仍兼容 `名称=URL模板`。填写 `none` 或 `[]` 禁用第三方 fallback；留空使用旧程序默认的三个 HTTPS 服务（mcsrvstat、mcapi.us、minetools）。 |
| `statusTimeout` | 直连和 fallback 的单次超时，例如 `5s`。必须大于 0。 |
| `statusCacheTTL` | 状态缓存时间，例如 `25s`。必须大于 0，避免频繁探测游戏服。 |

状态页先尝试 Minecraft TCP 状态协议；直连失败时按配置的第三方 API 返回 fallback。解析兼容旧 Node 程序的三个默认接口：`api.mcsrvstat.us` 使用 `players.online/max`、`version`、`motd.clean` 和 `debug.error`；`mcapi.us` 使用 `players.now/max`、`server.name` 和 `motd`；`api.minetools.eu` 支持数字或对象形式的 `players`、字符串或对象形式的 `version`，并读取 `description`/`motd`。`statusServers` 为空时状态页不展示服务器。第三方 URL 只能使用 `http://` 或 `https://`，不支持文件协议；不要把内网主机地址发送给不可信的第三方 API。

## 插件 listener

白名单和兑换接口只走内网，游戏服直接连接 Go 服务的内网 listener，不需要公网反向代理。默认地址是 `127.0.0.1:18094` 和 `127.0.0.1:18095`；跨机器时将地址改成服务端本机私网 IP，并在防火墙中只允许游戏服访问。GitHub 部署 ZIP 不含插件 JAR 或配置模板；需要插件时，从仓库 `plugins/whitelist` 和 `plugins/coupon` 工程单独构建，再将 JAR 放入 Leaves/Paper 服务端的 `plugins/` 目录。插件首次启动会生成配置文件，token 必须替换为对应 scope 的新签发值。

每台游戏服分别签发 whitelist 和 coupon token，二者不能复用。推荐使用交互菜单；它会读取当前数据目录、选择插件、填写游戏服可访问的服务端私网 IP，并自动生成对应的端口、路径和配置片段。token 明文只显示一次：

```sh
./gbcserver-linux-amd64 plugin-token
./gbcserver-linux-amd64 plugin-token --data-dir "$HOME/gbcserver"
```

管理员网页的“插件接入”页可以签发、查看和撤销令牌；“运行配置”页可以修改运行配置、重载或停止服务，并安装或移除当前用户的开机自启。自动化部署仍可使用 `plugin-token issue|revoke` 参数模式。白名单和兑换令牌共用同一个 `server_id`，必须与数据库 `serverID` 配置相同；两者仍是不同 scope、不同 `token_id` 和不同 secret。默认服务 ID 为 `default`。修改 `serverID` 后重新签发两种令牌并更新插件配置。

默认模板 URL 仅适用于 Go 与游戏服同机。跨机器时使用 Go 主机私网 IP 字面地址，并在管理员配置页将 `whitelistListen`、`couponListen` 改为该私网 IP；两侧端口只允许游戏服访问。Web 与插件 listener 是不同的端口和网络边界。

## 自启与控制

```text
gbcserver start --autostart --data-dir <data目录>
gbcserver start --no-autostart --data-dir <data目录>
gbcserver install-autostart --data-dir <data目录>
gbcserver uninstall-autostart --data-dir <data目录>
```

Linux 自启使用当前用户 systemd unit；Windows 自启使用当前用户 Run 项。后台实例的日志和 PID 在 `gbcserver/` 内。本机控制通道使用权限为 0600 的 Unix socket（Linux）或本机 TCP 管道（Windows），状态文件只用于定位当前实例。管理员网页可重新加载或停止托盘/后台实例；启动和自启安装/移除仍需在主机本地执行。`init-db`、`upgrade-db` 和 `migrate` 仅用于本机或离线维护。

## Windows 发布

正式发布的 Windows 程序应使用受信任的代码签名证书签名。打包脚本默认拒绝未签名或不受信任的文件；本地测试包可显式使用 `-SkipWindowsSignatureCheck`，不要将跳过校验的程序作为正式发布物。

## 数据库升级与迁移

新数据库会自动创建当前 schema。已有 Go 数据库可离线执行：

```text
gbcserver upgrade-db --db <SQLite文件>
```

旧 Node 数据库迁移仍使用 `migrate` 的 dry-run 与 `--apply` 两步流程。迁移和升级前停止服务并备份 SQLite；不要让 Node 和 Go 同时写同一个数据库。

## 帮助与退出码

`gbcserver help` 显示总帮助，`gbcserver help httpport`、`gbcserver help admin-password` 显示具体命令帮助。参数错误返回 2，运行或数据库错误返回 1，成功返回 0。帮助只打印固定文本，不读取密码、TOTP、数据库或外部服务。

### 图片压缩

头像和商品图片上传后会自动压缩：头像 PNG 和商品 PNG/JPEG 会缩放并重新编码，头像最长边限制为 256 像素，商品图片最长边限制为 512 像素；新上传不接受 GIF/WebP，历史 GIF/WebP 文件会在手动压缩时保留原格式以避免破坏动画。已经存在的生产图片可在停服后执行：

```text
gbcserver compress-images --data-dir <data目录> --dry-run
gbcserver compress-images --data-dir <data目录>
```

第一条只统计将要改写的文件，第二条实际写回 `avatars/` 和 `web/items/`。可用 `--max-dimension` 调整商品图最长边（32-4096），用 `--quality` 调整 JPEG 质量（1-100）；头像仍不会超过 256 像素。该命令只改图片文件，不改 SQLite 中的头像或商品图片引用。
